# ZERYNX VPN — Control Panel

پنل مدیریتی ZERYNX با رابط فارسی RTL، داشبورد، مدیریت اشتراک‌ها و موتور مستقل VLESS روی Cloudflare Workers.

## معماری استقرار

این نسخه با **یک Cloudflare Worker** اجرا می‌شود:
- رابط پنل از پوشه worker/public به‌عنوان Static Assets ارائه می‌شود.
- API، احراز هویت، صدور اشتراک و انتقال TCP در همان Worker اجرا می‌شوند.
- اطلاعات مدیر، کاربران، اشتراک‌ها و رویدادها در Cloudflare D1 ذخیره می‌شوند.
- نیازی به VPS، GitHub Pages یا سرویس میانی جداگانه نیست.

## استقرار با Cloudflare Dashboard

### ۱) دیتابیس D1
1. در Cloudflare وارد Workers & Pages → D1 SQL Database شو.
2. دیتابیس جدیدی بساز؛ مثلاً zerynx-control-db.
3. از Overview مقدار Database ID را کپی کن. این شناسه محرمانه نیست.

### ۲) اتصال دیتابیس به ریپو
1. در GitHub فایل worker/wrangler.toml را باز کن.
2. مقدار database_id را با Database ID واقعی جایگزین کن؛ مقدار تمام‌صفر فقط placeholder است.
3. مقدار name را دقیقاً برابر نام Worker موجودت قرار بده تا همان Worker به‌روزرسانی شود. اگر نام متفاوت باشد، Wrangler ممکن است Worker دیگری بسازد.
4. Commit را روی شاخه main ثبت کن.

### ۳) کلید نصب مدیر
در Cloudflare → Worker → Settings → Variables and Secrets:
1. یک Secret با نام BOOTSTRAP_SECRET بساز.
2. مقدار آن را با Password Manager تولید کن؛ حداقل ۳۲ کاراکتر تصادفی توصیه می‌شود.
3. مقدار Secret را در GitHub یا چت قرار نده.

### ۴) اتصال ریپو و Deploy
1. Cloudflare → Workers & Pages → Create → Import a repository.
2. ریپوی ZerynxIT/ZERYNX-VPN و شاخه main را انتخاب کن.
3. Root directory را worker قرار بده.
4. Build command خالی باشد.
5. Deploy command را این قرار بده:
   
   npx wrangler d1 migrations apply DB --remote && npx wrangler deploy

6. مجوزهای اتصال GitHub به Cloudflare باید اجازه Deploy Worker و اجرای Migration روی D1 را داشته باشند.
7. Deploy را اجرا کن. آدرس HTTPS Worker را باز کن؛ خود پنل باید از همان آدرس نمایش داده شود.

### ۵) راه‌اندازی اولین مدیر
1. آدرس Worker را باز کن.
2. گزینه راه‌اندازی مالک را انتخاب کن.
3. نام کاربری اولیه admin است.
4. یک رمز اختصاصی حداقل ۱۲ کاراکتری وارد کن.
5. مقدار Secret یعنی BOOTSTRAP_SECRET را در فیلد کلید نصب وارد کن.
6. پس از ساخت موفق مالک، Secret نصب را از تنظیمات Worker حذف کن و Worker را مجدداً Deploy کن.

**ورود پیش‌فرض admin/admin وجود ندارد.** این اعتبارنامه عمومی برای پنل اینترنتی ناامن است.

## قابلیت‌های فعلی

- داشبورد و آمار کاربران، اشتراک‌های فعال و حجم مصرف‌شده
- ایجاد اشتراک با حجم و اعتبار
- فهرست کاربران و جست‌وجو
- تعلیق/فعال‌سازی اشتراک
- چرخش لینک خصوصی اشتراک
- رویدادهای مدیریتی
- تغییر مشخصات حساب مالک
- لینک اشتراک VLESS
- سهمیه‌بندی اتمی در D1 برای جلوگیری از عبور هم‌زمان چند اتصال از سقف حجم
- ارائه پنل و API از یک Worker

## محدوده فنی موتور

موتور فعلی یک پیاده‌سازی مستقل و مینیمال **VLESS v0 روی WebSocket + TLS** است:
- انتقال TCP به مقصدهای عمومی روی پورت‌های 80 و 443
- نام دامنه یا IPv4 عمومی
- مسیر WebSocket برابر /stream
- احراز هویت با UUID اشتراک
- کنترل اعتبار، تعلیق و حجم مصرفی با D1

این موتور هم‌ارز کامل NovaWorker یا Nova Proxy نیست. در این نسخه UDP، Mux، Early Data، IPv6 literal و پنل چندنودی واقعی پیاده‌سازی نشده‌اند. Cloudflare Workers جایگزین یک سرور Xray/V2Ray کامل با همه قابلیت‌ها نیست. این محدودیت‌ها عمداً در رابط و مستندات پنهان نشده‌اند.

## تست پس از Deploy

1. /api/health باید ok: true و database: connected برگرداند.
2. /api/setup/status پیش از ساخت مالک باید installed: false برگرداند.
3. وارد پنل شو و یک اشتراک آزمایشی با حجم کم بساز.
4. لینک اشتراک را در کلاینت سازگار با VLESS وارد کن و اتصال واقعی TCP را آزمایش کن.
5. مصرف را در داشبورد بررسی کن؛ پس از پایان حجم یا تعلیق، اتصال‌های بعدی باید رد شوند.

تست‌های GitHub Actions، تست‌های خودکار API و بررسی Syntax هستند؛ موفقیت آن‌ها به معنی تأیید اتصال واقعی از شبکه و کلاینت تو نیست.

## فایل preview.py چیست؟

preview.py فقط یک وب‌سرور ساده محلی روی پورت 3000 برای پیش‌نمایش فایل‌های رابط کاربری است. جزو موتور VPN نیست و برای Deploy روی Cloudflare لازم نیست.

## مجوز و الهام طراحی

نام، برند و پیاده‌سازی ZERYNX مستقل هستند. چیدمان مدیریتی از الگوهای رایج پنل‌های مدیریت اشتراک الهام گرفته است؛ کد موتور NovaWorker یا Nova Proxy در این پروژه کپی نشده است.
