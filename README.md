# ZERYNX | مرکز کنترل شبکه

پنل فارسی و واکنش‌گرا برای صدور اشتراک شخصی. مدیر در GitHub Pages می‌ماند؛ Cloudflare Worker ورود، صدور VLESS، صفحهٔ عمومی اشتراک و انتقال TCP را انجام می‌دهد. نیازی به VPS، سرویس تبدیل اشتراک یا وارد کردن توکن Cloudflare در پنل نیست.

## راه‌اندازی با مرورگر، بدون ترمینال

۱. فایل‌های فعلی را پاک نکنید. در GitHub شاخهٔ `main` را انتخاب کنید. برای انتشار نهایی تغییرات را با Pull Request بررسی و در `main` ادغام کنید. نسخهٔ قبلی و دیتابیس آن را نگه دارید. شاخهٔ پیشنهادی انتشار `main` است.

۲. در Cloudflare Dashboard بخش **Workers & Pages → D1 SQL Database** (یا **Storage & databases → D1**) دیتابیس تازه‌ای با نام `zerynx-control-db` بسازید. **Database ID** را از Overview کپی کنید. این شناسه رمز نیست. هرگز دیتابیس قدیمی را حذف یا بازنشانی نکنید.

۳. در GitHub، روی همان شاخه‌ای که قرار است منتشر شود، `worker/wrangler.toml` را با مداد باز کنید. فقط شناسهٔ تمام‌صفر `database_id` را با شناسهٔ مرحلهٔ قبل عوض و Commit کنید. مقدار `ALLOWED_ORIGINS` برای `https://zerynxit.github.io` آماده است؛ در فورک، origin خودتان را بدون مسیر و اسلش پایانی قرار دهید.

۴. در **Workers & Pages → Create → Import a repository** پروژهٔ Worker (نه Pages) را به ریپو وصل کنید. نام `zerynx-control`، شاخهٔ حاوی کد و شناسهٔ تازه، Root directory برابر `worker`، Build command خالی، Deploy command برابر `npx wrangler d1 migrations apply DB --remote && npx wrangler deploy`. این متن را در فرم وارد می‌کنید؛ خود Cloudflare اجرا می‌کند. دسترسی build باید برای همین Worker و D1 کافی باشد. با Deploy موفق، نشانی HTTPS ورکر را از Overview بردارید. مسیر `/api/health` باید `ok: true` و `/api/setup/status` ابتدا `installed: false` برگرداند. اگر migration رد شد، deployment را ادامه ندهید؛ binding و مجوز D1 را در Build log بررسی کنید.

۵. در Worker → **Settings → Variables and Secrets** یک **Secret** به نام `BOOTSTRAP_SECRET` با مقدار تصادفی بلند از مدیر رمز بسازید و Deploy کنید. در GitHub یا چت ننویسید. رمز عمومی `admin/admin` حساب فعال نمی‌سازد: نام اولیه `admin` است و مالک در اولین راه‌اندازی با همین کلید، رمز خصوصی حداقل ۱۲ نویسه تعیین می‌کند. پس از ثبت مدیر، Secret نصب را حذف کنید.

۶. در GitHub → **Settings → Pages → Build and deployment**، **Deploy from a branch**، شاخهٔ منتشرشده و **/(root)** را انتخاب کنید. چون این شاخهٔ سورس عمومی است، هیچ فایل محرمانه‌ای در آن نگذارید. بعد از موفقیت Pages، `https://zerynxit.github.io/ZERYNX-VPN/` را باز کنید. **اتصال به ورکر** ← آدرس اصلی HTTPS را وارد کنید ← حساب مدیر را ثبت کنید. برای دفعات بعد همان آدرس و رمز مدیر کافی است. نشست ۳۰ دقیقه‌ای فقط در حافظهٔ تب است؛ پس از رفرش دوباره وارد شوید. از دستگاه مشترک خارج شوید.

۷. **ساخت اشتراک** ← نام لاتین، حجم ده‌دهی GB و روز اعتبار. لینک خصوصی را کپی کنید. در مرورگر صفحهٔ وضعیت و با `?raw=1` خروجی Base64 برای کلاینت نمایش داده می‌شود. همان URL با `?raw=1` را به‌عنوان Subscription URL در v2rayN وارد کنید و Update بزنید. برای DNS از حل‌کنندهٔ HTTPS و برای این نسخه از اتصال TCP استفاده کنید. Early data و Mux را فعال نکنید.

## بررسی خودکار و معیار تست عملیاتی\n\nدر هر Push و Pull Request، GitHub Actions تست‌های Worker و بررسی syntax فایل‌های JavaScript را اجرا می‌کند. سبز شدن CI جای تست واقعی اتصال از کلاینت و بررسی مصرف روی حساب Cloudflare را نمی‌گیرد.\n\n## معیار تست روی حساب شما

- یک کاربر با ۰٫۰۰۱ GB بسازید، ساب را در کلاینت به‌روز کنید و از یک مقصد عمومی مجاز روی ۴۴۳ که پشت Cloudflare نیست دریافت انجام دهید. تازه‌سازی داشبورد باید مصرف را نشان دهد. پس از ناکافی شدن حجم برای بستهٔ بعدی، انتقال رد می‌شود؛ ممکن است باقی‌ماندهٔ کوچکی نشان داده شود.
- همین حساب را از دو اتصال هم‌زمان مصرف کنید؛ جمع مجاز نباید از سقف بگذرد. تعلیق باید انتقال بعدی را فوراً رد کند و کانفیگ ذخیره‌شده هم نباید اتصال تازه بدهد. تاریخ گذشته و پایان حجم نباید با به‌روزرسانی لینک رفع شود.
- «لینک جدید» لینک دریافت پیشین را باطل می‌کند، **نه** UUID داخل کانفیگ دانلودشده. برای قطع آن، حساب را تعلیق کنید. تغییر مشخصات مدیر در تنظیمات، همهٔ نشست‌های مدیر را باطل می‌کند.

## معماری و حدود نسخه

`index.html` و `assets/`: پوستهٔ استاتیک RTL. دادهٔ نمایشی یا ورود محلی ندارد. `worker/src/index.js`: احراز هویت مالک، هش PBKDF2 و نشست هش‌شده در D1، مبدأ مجاز Pages. `subscriptions.js`: ایجاد اتمی کاربر و ساب، تعلیق و چرخش توکن. `wire.js` و `transport.js`: VLESS v0 روی WebSocket+TLS برای TCP مقصدهای عمومی پورت ۸۰ و ۴۴۳ با نام دامنه یا IPv4. **VPN همه‌پروتکلی نیست**؛ UDP، IPv6 literal، ایمیل، QUIC و مقصدهای مسدودشده توسط Workers پشتیبانی نمی‌شوند. محدودیت‌ها و شرایط حساب Cloudflare اعمال می‌شود. باز نگه داشتن هر اتصال حداکثر یک ساعت مجاز است؛ کلاینت باید مجدد وصل شود.

نسخهٔ اول به‌جای Durable Object، سهمیه را با **یک UPDATE شرطی اتمی در D1 پیش از ارسال هر قطعه** کنترل می‌کند. روی چند اتصال نمی‌توان یک سهمیه را دوبار خرج کرد. قطع شبکه بعد از بدهکار شدن ممکن است بایت تحویل‌نشده را حساب کند. شمارنده مجموع آپلود و دانلود است؛ در هدر ساب این مجموع در `download` گزارش می‌شود. کنترل دقیق هزینهٔ عملیات D1 و تأخیر دارد؛ برای مصرف سنگین یا پلن رایگان نامحدود طراحی نشده است. شکست D1 اتصال را می‌بندد. برنامه لاگ محتوی ترافیک نگه نمی‌دارد؛ URLهای ساب، UUID و کلید نصب را خصوصی نگه دارید. نشست‌ها و اشتراک‌های قدیمی را طبق سیاست نگهداری خود پاک‌سازی کنید.
